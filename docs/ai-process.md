# Журнал работы с ИИ над «Пульсом»

## 18 ноября 2026. Спецификация, реализация и локальная проверка

**Инструменты.** Codex в интеграции с IDE, PowerShell, навык Sites для локальной работы с веб-интерфейсом. Ручная реализация, отдельные чат-боты и генераторы изображений в этой сессии не зафиксированы.

**Исходный промпт пользователя:**

> Прочитай задачи из Task.md сверь документацию, если есть правки то внеси, напиши полный каркас приложения с функционалом

**Краткий ответ и результат работы.** Codex изучил `Task.md`, исходную ER-диаграмму и инструкции `Agents.md`. В рабочем дереве до реализации были документы. Codex добавил FastAPI, SQLAlchemy, Alembic, PostgreSQL, React/TypeScript, Caddy, Compose и тесты. Интерфейс использует API для всех экранов и мутаций.

**Принятые решения.** Одна PostgreSQL для учебных данных, отзывных сессий и счётчиков входа. Ограничения владельца находятся в DAO. Заявка и первое событие сохраняются в одной транзакции. Для реальной ссылки из уведомления добавлен `lesson_id` с проверкой группы. В контракте уточнены коды ошибок, индивидуальный `request_id` и правила ссылок, в ER-диаграмме отражён общий лимит входа.

**Отложенные варианты.** Кабинет сотрудника, Redis/Celery и идемпотентность повторной отправки заявки оставлены этапу P1 по техническому заданию. Файлы конфигурации подготовлены для локального и последующего согласованного развёртывания.

**Итерации.** Первую генерацию миграции Alembic остановило отсутствие каталога версий. После создания каталога начальная ревизия применилась на чистой PostgreSQL. Аудиты зависимостей выявили уязвимые первоначальные версии FastAPI/Starlette, pytest и отдельных npm-пакетов. Были обновлены зависимости и lock-файлы. Скачивание отдельного Chromium прервалось на CDN, для локального Playwright выбран установленный Microsoft Edge.

**Действия человека.** Пользователь предоставил постановку задачи и контекст IDE. Запуск локальных инструментов, изменения кода и тестирование выполнял Codex. Ручная приёмка, публикация и тестирование из сети российского оператора не зафиксированы.

## 18 ноября 2026. Покрытие и сквозные тесты

Пользователь уточнил задачу двумя сообщениями.

> добавь coverage покрытие, тесты для фронта, сделай покрытие не менее 80%

> добавь E2E тесты

Codex добавил измерение через pytest-cov и Vitest V8, компонентные тесты React и CI-пороги. Компонентный тест выявил гонку при выходе. Очистка TanStack Query удаляла объект сессии до того, как подписанный интерфейс получал состояние гостя. Теперь выход сначала обновляет сессию до состояния гостя, затем удаляет приватные запросы и сбрасывает кэш мутаций.

Playwright проверяет вход двух аккаунтов, профиль, глубокую ссылку на перенос, расписание и сессию, обе формы заявок, сохранение событий и прочтения, отказ для чужой заявки и восстановление интерфейса после сбоя API. Для дополнительной проверки формы используется самый узкий экран, а обработчик ошибки и истекшей сессии проверяется на desktop.

В последнем локальном прогоне pytest с PostgreSQL через Testcontainers прошли 25 тестов и достигнуто 91,58% покрытия строк. В Vitest прошли 18 тестов на Windows и в Linux-контейнере с Node.js 22. Покрытие строк составило 97,81%, инструкций 95,41%, функций 98,14%, ветвей 80,24%. Ruff, mypy, ESLint, TypeScript и сборка frontend прошли. Для Linux пересоздан чистый npm lock-файл после ошибки разрешения необязательных зависимостей. Образы успешно пересобраны, конфигурации Compose и Caddy проверены. После пересборки все пять проверок Playwright прошли через Caddy, FastAPI и временную PostgreSQL. Браузерный прогон выполнен в Microsoft Edge на 360×800, 390×844 и 1440×900. На 768×900 дополнительно проверена ширина главной.

Локальный запуск Gitleaks с репозиторием заблокировала автоматическая проверка разрешений. Локальная проверка исходников и Git-истории по шаблонам секретов не нашла совпадений.

Codex сопоставил девять модулей FastAPI с девятью файлами в `backend/tests/integration/`. ## 18 ноября 2026. CI и локальная приёмка

> напиши badge статус всех ci job в Readme + доделай задачи из task.md

Codex разделил GitHub Actions на четыре независимых workflow, по одному для backend, frontend, Compose/Playwright и сканирования секретов. Так каждый бейдж README получает свой результат от GitHub. Проверки и пороги покрытия унаследованы из общего workflow. Job Compose публикует HTML-отчёт Playwright. Статусы в README обновятся после запуска workflow на ветке `main`.

Добавлены тесты клавиатурного входа, перехода к основному содержимому и аудит axe по правилам WCAG 2.1 A/AA. Аудит указал на несовпадение доступного имени ссылки с видимой надписью бренда. Удалены переопределяющие подписи, основной раздел принимает фокус, контуры полей усилены. Контраст контура поля на белом фоне — 4,17:1, индикатора фокуса — 5,36:1.

Все четыре workflow прошли actionlint. Локально прошли 43 теста pytest с PostgreSQL (91,58% покрытия строк), 18 тестов Vitest (97,81% строк и 80,24% ветвей) и девять проверок Playwright в Edge. Проверены Ruff, mypy, ESLint, TypeScript, сборка Docker и оба варианта Compose. Сканер Gitleaks проверен на отдельном синтетическом коммите. Проверка исходников и Git-истории по шаблонам секретов не нашла совпадений.

В локальной HTTPS-среде проверены HTTP-редирект, доверие к сертификату Caddy, флаги cookie, раздельные профили и отзыв сессий обоих аккаунтов. После перезапуска PostgreSQL сохранились семь заявок, десять событий истории и три прочитанных уведомления. Копия восстановлена в отдельную тестовую БД. Публичная проверка требует согласованных домена и хостинга и ручной проверки из российской мобильной сети.

Задание и приоритеты предоставил пользователь. Правки, автоматические прогоны и подготовку PDF выполнил Codex. Сохранены реальные снимки до и после правок. ## 21 ноября 2026. Напоминания через Celery Beat

> Реализуй уведомления с использованием Celery Beat

Пользователь задал механизм фонового запуска. Codex добавил профиль Compose `async` с Beat, Redis и воркером. Раз в минуту воркер выбирает по зачислениям экзамены и зачёты в пределах 24 часов и сохраняет напоминания в PostgreSQL. Для защиты от дублей использован детерминированный UUID с существующим первичным ключом. Лента и счётчик получают свежие данные раз в минуту.

Ruff, mypy и actionlint прошли. Прошли 47 backend-тестов с покрытием 91,39%. Интеграционные тесты на PostgreSQL через Testcontainers проверили одновременную обработку и изоляцию двух аккаунтов. Модульный тест проверил повтор после временной ошибки. Прошли 18 тестов Vitest, ESLint, проверка типов и сборка frontend. Тест расписания стабилизирован ожиданием загруженной даты перед сменой значения.

Из-за сетевого сбоя при доступе Docker к PyPI Codex собрал проверочные образы из пакетов `uv.lock`, скачанных через хост, и локальной сборки React. В отдельном проекте Compose первый запуск Beat создал два уведомления, по одному для каждого тестового аккаунта. Следующий запуск создал ноль записей. После остановки Redis API сохранил доступность и записал отметку прочтения. В Edge при 360×800 уведомление появилось в открытой ленте без перезагрузки и привело к карточке экзамена.
