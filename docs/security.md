# Безопасность «Пульса»

Доверенная область начинается на сервере. Студент определяется по проверенной сессии, занятия — по его группе, оценки и экзамены — через его зачисления. Запросы заявок и уведомлений ограничены владельцем непосредственно в SQL. Сервер дополнительно проверяет доступ к объектам в полиморфных ссылках уведомлений.

| Угроза | Контроль | Проверка |
|---|---|---|
| Несанкционированное чтение | Действующая сессия и активный пользователь | Гость получает 401 на приватных маршрутах |
| Подмена владельца или UUID | Серверный scope, строгие DTO, одинаковые ошибки 404 | Два клиента с разными профилями, отказ на чужой UUID, лишние body/query поля |
| Подделка запроса | Точный Origin, сессионный CSRF, JSON для входа | Пустой CSRF, неверный CSRF и чужой Origin отклоняются |
| Повторное использование сессии | SHA-256 токена в БД, отзыв при выходе и повторном входе | Копия ранее выданной cookie даёт 401 |
| Подбор пароля | Общие счётчики PostgreSQL, ограничения по имени и адресу | Независимые экземпляры API разделяют счётчики |
| Утечка в кэш или журналы | no-store, безопасные ошибки, структурированные журналы | Контракт JSON, флаги cookie и очистка кэша клиента |
| Повтор и конкуренция | Транзакция заявки и истории, атомарное сохранение первого read_at | Чтение после новой сессии и повтор отметки |

CI проверяет все зависимости Python и npm. Для npm сначала проверяются зависимости приложения, затем полный lock-файл. Допускается только открытый advisory для `picomatch` в инструментах сборки. В финальном образе Caddy обслуживает статический результат Vite, а инструменты сборки остаются в промежуточном образе. На 18 ноября 2026 исправленная версия отсутствует. [Запись GitHub Advisory Database](https://github.com/advisories/GHSA-fc5q-39xc-vjpf)

Лицензии ключевых библиотек интерфейса проверены по метаданным установленных пакетов. React, React DOM, React Router, TanStack Query и Tailwind CSS используют MIT, Lucide React использует ISC. `@axe-core/playwright` использует MPL-2.0 и запускается в тестах.

Первую миграцию разворачивают на пустой БД. Для отката приложения возвращают предыдущий образ, а при несовместимости восстанавливают проверенную резервную копию в отдельную БД. Удаляющий таблицы downgrade допустим только в одноразовой тестовой БД.
